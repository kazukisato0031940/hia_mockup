## 1. ロールとサブロール（変更 D）

### 1.1 サブロール

- **企業担当者** のアカウントに、任意で **サブロール** を1つ付与できる。
  - `産業医（doctor）` … 医学的判断を行う担当者
  - `人事（hr）` … 運用事務を行う担当者
  - サブロールなし … 従来どおりの企業担当者
- サブロールを付与できるのは **企業担当者ロールのみ**。健保担当者・当社スタッフには付与できない（フォームから送られても無視する）。
- 権限ロール・閲覧範囲・担当範囲は従来どおり。サブロールはその上に重ねる区分で、**機能制御のキー**（第2章）と、面談管理での**操作可否**（第4章）を分けるために使う。

### 1.2 機能制御上のロールキー

機能制御・表示列の保存などは、次の5区分で扱う。

| ロールキー | 表示名 |
|---|---|
| `system_admin` | 当社スタッフ |
| `kenpo_user` | 健保担当者 |
| `company_user` | 企業担当者（サブロールなし） |
| `company_user/doctor` | 企業担当者（産業医） |
| `company_user/hr` | 企業担当者（人事） |

### 1.3 肩書きの表示

- 一覧・確認画面・メモ・報告書に出すロール表記は、サブロールがあれば「企業担当者（産業医）」のように併記する。
- アカウント一覧では、ロールのバッジの下にサブロールのバッジを表示する。ロール絞り込みに「企業担当者（産業医）」「企業担当者（人事）」を追加する。

## 2. 機能制御（新機能 B）

### 2.1 目的

ロール・サブロールごとに「使える機能」を当社スタッフが画面から切り替えられるようにする。
画面のボタンやメニューを隠すだけでなく、URL を直接呼ばれた場合もサーバ側で拒否し、監査ログに記録する。

### 2.2 機能キー一覧

|---|---|---|---|

| 産業医面談 | `oh.list` | 面談対象者一覧 | |
| 産業医面談 | `oh.kenshin` | 健診受診管理（定期・深夜） | |

| 産業医面談 | `oh.sign` | 報告書への記名・サイン | **固定** |
| 産業医面談 | `oh.hr_class` | 対応区分の設定 | |

| そのほか | `download` | CSVのダウンロード（アカウントごとのDL権限とAND判定） | |

### 2.3 判定ルール

1. **固定の機能**（`oh.approve` / `oh.interview` / `oh.sign` ＝ 医学的判断）は、設定に関係なく **企業担当者（産業医）だけ** が使える。設定画面でも変更できない。
2. **当社スタッフ**は、固定の機能を除き、設定に関係なく **常にすべての機能** を使える（機能制御の対象外）。
3. それ以外のロールキーは、
   - 設定（保存済みの利用可否）があればそれに従う
   - 無ければ **既定値**（下表）に従う

### 2.4 既定値（「初期値に戻す」で戻る状態）

| ロールキー | 既定で使える機能 |
|---|---|
| 当社スタッフ / 健保担当者 / 企業担当者 / 企業担当者（人事） | マスタ閲覧・登録・取込、面談一覧・健診・対応区分・報告・メール・取込、健保管理の全業務、疾患予測、アカウント管理、DL |
| 企業担当者（産業医） | マスタ**閲覧のみ**、面談一覧・健診・報告、**面談承認・面談記録・記名（固定）**、疾患予測、アカウント管理、DL（＝取込・メール配信・健保管理の各業務・対応区分は既定で持たない） |

### 2.5 設定画面（`/settings/features`、当社スタッフのみ）

- 機能キー（行）×ロールキー（列）のマトリクスにチェックボックスを表示する。
- 「当社スタッフ」列は常に利用可（切替不可）。固定の機能の行は「企業担当者（産業医）」のみ利用可（切替不可）。
- 保存すると、変更点を「ロール名／機能名＝利用可（不可）」の形で監査ログに残す。
- 「初期値に戻す」で保存済みの設定をすべて削除し、既定値に戻す。
- 変更は **各アカウントの次のアクセスから** 適用される。

### 2.6 拒否時の挙動

- 機能が利用不可のロールで対象URLを呼ぶと **403** を返し、`denied` 画面に「機能制御の設定で『（機能キー）』が利用不可になっています」と表示する。
- 監査ログに `role=（ロールキー）／機能=（キー）` を残す。

## 3. マイアカウント（新機能 C）

- 画面: `/me`（ヘッダーの「マイアカウント」／シェルの利用者名クリックから開く）
- **本人が変更できる項目**: 利用者名、メールアドレス（＝ログインID）、パスワード
- **本人が変更できない項目**: 権限ロール、サブロール、閲覧範囲、担当範囲（自分で権限を広げられないようにするため。変更は他の管理者が行う）
- メールアドレス変更時: 形式・重複を検証し、**変更前・変更後の両方のアドレス** へ通知メールを送る。
- パスワード変更時: **現在のパスワードの確認** を必須とし、現在と同じものは設定不可。変更後、登録アドレスへ通知メールを送る。パスワードそのものはログに残さない。
- **サポートログイン中は変更不可**（誤操作防止）。
- アカウント一覧で自分の行は「自分の情報を編集」ボタン（`/me` へ）に変わり、「権限の変更は他の管理者へ依頼してください」と表示する。

## 4. 産業医面談管理（新機能 A）

### 4.1 位置づけ

労働安全衛生法に基づく「健康診断」「長時間労働（過重労働）」「ストレスチェック」の情報を横断し、
**産業医面談の対象者抽出 → 承認 → 受診勧奨 → 面談記録 → 労基署報告** までを支援する。
加入者・企業・事業所・部署は本システムの既存マスタをそのまま使う。

画面はシェル（統合画面）内のカテゴリ「産業医面談」に、次のサブメニューで配置する。

| サブメニュー | パス | 機能キー |
|---|---|---|
| 面談対象者一覧 | `/oh/` | `oh.list` |
| 定期健診 受診管理 | `/oh/kenshin` | `oh.kenshin` |
| 深夜健診 受診管理 | `/oh/kenshin?kind=深夜` | `oh.kenshin` |
| 面談結果入力 | `/oh/interview` | `oh.list`（保存は `oh.interview`） |
| 労基署報告 | `/oh/report` | `oh.report` |
| メール配信 | `/oh/mail` | `oh.mail` |
| データ取込 | `/oh/upload` | `oh.upload` |

### 4.2 操作可否（産業医と運用事務の分担）

| 操作 | 産業医（doctor） | それ以外（人事・企業担当者・健保担当者・当社スタッフ） |
|---|---|---|
| 面談対象の**承認 / 承認解除 / 面談不要（対象外）** | ○ | × （送信されてもサーバ側で無視・記録） |
| **就業区分**（通常勤務／就業制限／要休業）の判定 | ○ | × （同上） |
| **面談記録**の登録 | ○ | × |
| 報告書への**記名・サイン** | ○ | × |
| **対応区分**（未判定／産業医判定済／要精査・加療指示／保健師対応中／再検査対応指示）の設定 | ―（既定で持たない） | ○（`oh.hr_class` が利用可のロール） |
| データ取込・メール配信・報告書出力・CSV/PDF出力 | ―（既定で持たない） | ○ |
| メモの追記 | ○ | ○ |

> 医薬品・疾患・治療に関する表示は参考情報であり、就業判定・措置の最終判断は産業医・医師が行う前提の画面構成とする。

### 4.3 年度

- すべての集計・記録は **年度（4月〜翌3月）** 単位で扱う。
- 画面上部で対象年度を切り替える（既定は当年度、選択肢は直近5年度）。

### 4.4 判定区分

- 総合判定は **日本人間ドック・予防医療学会の判定区分（2026年4月1日改定）** に準拠：A（異常なし）／B（軽度異常）／C（要再検査・生活改善）／D（要精密検査・治療）／E（治療中）。
- **有所見** = C 判定以上（C／D／E）。
- 取込データの旧表記（「要注意」「要医療」「基準内」「1〜5」等）は A〜E に自動マッピングする。判別できない値はエラーとする。
- 複数の判定があるときは **最も重いもの** を採用する。

### 4.5 B. 対象者スクリーニング（`/oh/`）

**面談候補の自動抽出**（一覧を開くたびに再評価し、理由が変わったら更新）:

| 抽出条件 | 判定基準 |
|---|---|
| 健診有所見 | 総合判定が C／D／E |
| 長時間労働 | 年度内のいずれかの月の時間外労働が **80時間超**（100時間超は水準を区別して表示） |
| 高ストレス | ストレスチェックで高ストレス者と判定（本人からの面接指導の申出があれば併記） |

- 複数該当時は理由を併記する。
- 候補のワークフロー（ステータス）: `産業医確認待ち` → `面談対象（承認済）` → `勧奨メール送信済` →（`面談予約済`）→ `面談完了` ／ 別枠で `対象外`。
- 一覧では、氏名・社員ID・部署・年齢・健診判定・抽出理由・時間外・ストレス・メモ・ステータスを表示。**表示列はロール（サブロール）単位で保存**できる（氏名は必ず表示）。
- 業務フローナビに、候補・確認待ち・承認済・送信済・面談完了・対象外の件数を表示。
- 絞り込み: 氏名／部署／企業、健診判定（複数選択）、抽出条件、ステータス、対応区分、受診有無。
- **確認・処理モーダル**（B）: 1名または複数名まとめて、承認／承認解除／対象外、就業区分、対応区分、メモを反映する。
  - 承認時・就業区分の判定時に、対応区分が「未判定」なら自動で「産業医判定済」にする。
  - 承認前に就業区分だけ判定した場合も「面談対象（承認済）」として扱う。
- **対象者詳細**（`/oh/member/<id>`）: 健診結果票（前年比較つき明細）、時間外労働の月次推移、ストレスチェック、メモ履歴（記入者・ロール・日時）、面談記録を表示。
- **一括出力**: 健診結果・面談状況の CSV（B-16）、健診結果票の PDF（印刷画面、最大100名、B-17）。

### 4.6 C. 健診受診管理（`/oh/kenshin`）

- 年度・健診区分（**定期／深夜**）ごとに、対象者・受診済・未受診・有所見の件数と **受診率** を表示。
- **深夜健診** は、加入者マスタの **深夜業従事区分** が立っている加入者のみを対象とする。
- 深夜業従事区分は本画面から加入者ごとに変更でき、変更は監査ログに残す。

### 4.7 D. メール配信（`/oh/mail`）

- 1画面で **面談受診勧奨** と **ストレスチェック受検案内** を配信する。
- 配信テンプレート（件名・本文）を種別ごとに登録・編集。差し込み項目 `{{氏名}}` `{{予約URL}}` `{{回答期限}}`。
- **面談受診勧奨**は「面談対象（承認済以降）」のみ送信し、非対象は **スキップ**（履歴に記録）。送信成功で候補を「勧奨メール送信済」にし、送信回数・最終送信日時を更新（リマインド対応）。
- **ストレスチェック案内**は全加入者へ送信し、実施記録（キャンペーン：対象期間・期限・送信数）を残す。
- SMTP 未設定時は本体と同じく `outbox` に控えを書き出す。
- 配信履歴（種別・対象者・件名・日時・実行者・結果）を表示。

### 4.8 E. 面談結果入力（`/oh/interview`）

- 一覧は「面談対象（承認済以降）」と、すでに面談記録があるものを表示。
- 記録項目: 面談日、方法（対面／オンライン／電話）、目的（健診有所見／長時間労働／高ストレス／本人からの申出／その他）、就業区分、事後措置、産業医所見、次回予定、面談時点の直近の時間外労働。
- **登録は産業医のみ**。保存すると候補ステータスを「面談完了」にし、対応区分が「未判定」なら「産業医判定済」にする。労基署報告の「面接指導実施状況」に反映する。
- 年度内は1加入者1件（上書き）。

### 4.9 F. 労基署報告（`/oh/report`）

- 社内管理用サマリーと、提出書類2種を表示・出力する。
  - **定期健康診断結果報告書（様式第6号）**相当（`kind=kenshin`）
  - **心理的な負担の程度を把握するための検査結果等報告書（ストレスチェック結果等報告書）**相当（`kind=stress`）
- 集計項目: 在籍労働者数・受診者数・未受診者数・受診率・有所見者数、判定区分別人数、深夜健診対象/受診、面接指導 対象/実施/未実施、就業区分別人数、ストレスチェック 対象/受検/高ストレス/申出/高ストレス者の面接指導実施。
- **産業医の記名・サイン**（`oh.sign`、産業医のみ）: 年度・種別ごとに氏名・所属/資格を登録。次回以降の初期値として保持。
- 出力: 印刷（PDF）画面、集計 CSV。出力操作は監査ログ（ダウンロード）に残す。

### 4.10 G. データ取込（`/oh/upload`）

3種の CSV を取り込む。各行を **社員コード → 被保険者証番号 → 氏名 → 被保険者証番号(subscriber_id)** の順で加入者マスタに突合し、一意に決まらない行は「要確認」として件数と行番号を返す。

| 種別 | 主な列 | 取込先 |
|---|---|---|
| 労働時間 | 社員コード、対象年月（YYYY-MM）、時間外労働時間、休日労働時間 | 月次の時間外労働 |
| ストレスチェック | 社員コード、実施年度、受検日、合計点、高ストレス者、面接指導の申出 | ストレスチェック結果 |
| 健診結果 | 社員コード、受診年度、健診区分、受診日、総合判定、産業医所見 | 健診受診記録 |

- 各種別の **取込フォーマット CSV**（見本1行つき）を配布する。
- **本システムの健診結果連携から総合判定を生成**: 既存の健診結果（検査項目ごとの判定）から、最も重い判定を学会区分に読み替えて総合判定として登録する。
- ストレスチェック **設問マスタ**（カテゴリ・番号・設問文）の追加・削除。
- 取込はいずれも監査ログ（インポート）に残す。

## 5. 既存機能への影響

### 5.1 アカウント管理（変更 D）

- 発行・編集フォームに **サブロール**（産業医／人事、企業担当者のときのみ有効）を追加。
- 確認画面（新規・編集）にサブロールのバッジを表示。確認→適用の再送信でサブロールを引き継ぐ。
- 一覧の絞り込み・行表示・エクスポートにサブロール列を追加。
- 編集画面・企業ピッカー（`_pickers.html`）まわりを、本マージのフォーム構造にあわせて整理（健保IDでの企業絞り込みロジックなどを簡素化）。

### 5.2 マスタ画面の「閲覧のみ」対応（変更 E）

- 企業・事業所・部署・加入者の一覧・詳細は `master.view`、追加・編集・削除・紐づけ・CSV取込は `master.write` / `master.import` で分離。
- `master.write` を持たないロール（例: 産業医）では、登録・編集・削除ボタン、チェックボックス、インポートUIを表示せず「閲覧のみ」と表示する。加入者画面の説明文も切り替える。

### 5.3 統合画面（シェル）（変更 F）

- `km_app.html` / `hia_app.html` に以下を追加:
  - **産業医面談** カテゴリと各サブ画面（iframe 埋め込み）
  - **マイアカウント**（利用者名クリックから）
  - **機能制御**（`/settings/features`）
  - マスタ（企業・事業所・部署・加入者）をシェル内に埋め込み表示
- シェルは静的HTMLのため、`/api/me` でログイン情報（`features` マップ・`role_key` 等）を取得し、`data-feature="（キー）"` を持つメニュー要素を **利用不可なら非表示** にする。
- `/api/me` の返却に `sub_role` / `sub_role_label` / `role_key` / `role_key_label` / `features` を追加。

### 5.4 権限エラー画面（変更 G）

- `denied.html` に、
  - ロール表記をサブロール併記（`role_full`）に変更
  - 機能制御で止められた場合は該当機能キーと「当社スタッフへご依頼ください」を表示

## 9. 本マージで取り込まなかった箇所（バグ修正の維持）

`templates/frag_base.html` は、マージ元との差分が **埋め込み画面の高さ測定のバグ修正のみ** だったため、
既存（Desktop 側）の修正版を維持し、マージ元の版で **上書きしていない**。

- 内容: iframe 内コンテンツ高さの測定を `document.documentElement.scrollHeight` から
  `Math.max(document.body.scrollHeight, document.body.offsetHeight)` に変更。
- 目的: 親が高さを広げるたびに iframe がさらに広がる「高さ増殖ループ」を止める。
- 参考: メモ [[hia-app-embed-height-bug]]。

このほか、Desktop 側のみの `docs/`・`.gitignore` は保持した。DB は、マージ元の DB で置き換えず
既存 DB に移行処理を適用してデータを保持した（バックアップ: `hia.db.bak` / `hia.db.premerge.*` / `backup/`）。
