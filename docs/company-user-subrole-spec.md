# HIA 企業担当者サブロール（人事・産業医）機能仕様書（実装非依存）

本書は、既存の「ログインアカウント管理」（[account-management-spec.md](account-management-spec.md) 第2部）に対する **追加仕様** を、実装非依存の振る舞い仕様として記述する。
データベース構造・テーブル名・フレームワーク・ファイル構成などの実装詳細は「付録」節を除き含まない。
本番システム側で本書を読み取り、本番システムのデータ構造に合わせて要件定義書を作成することを想定している。

## 1. 概要

### 1.1 追加の目的

企業担当者のログインアカウントには、これまで「権限ロール＝企業担当者」以下の区別がなかった。
産業医面談管理の導入にあたり、**同じ企業担当者でも担当業務が異なる**利用者を区別する必要が生じた。

- **人事担当者** … 運用事務（データ取込、対象者の管理、メール配信、対応区分の設定、帳票の出力）
- **産業医** … 医学的判断（面談対象の承認、就業区分の判定、面談結果の記録、労基署提出書類への記名）

このため、企業担当者ロールに **サブロール** という区分を1段追加する。

### 1.2 サブロールの値

| サブロール | 意味 | 主な役割 |
|---|---|---|
| （なし） | 従来どおりの企業担当者 | 運用事務。人事と同じ範囲 |
| **人事** | 企業の人事・労務担当者 | 運用事務（取込・管理・配信・対応区分・出力） |
| **産業医** | 企業が選任した産業医 | 医学的判断（承認・就業区分・面談記録・記名）。運用事務は行わない |

### 1.3 基本原則

1. サブロールは **企業担当者ロールにのみ** 付与できる。健保担当者・当社スタッフには付与できない。
2. サブロールは権限ロールを**置き換えない**。閲覧範囲・担当範囲・代表者区分などは従来どおりで、その上に業務区分として重ねる。
3. サブロールを持たない企業担当者は、**人事と同じ**業務範囲とする（後方互換）。
4. **医学的判断は産業医サブロールだけが行える**。これはシステム設定で変更できない固定の制約とする（労働安全衛生法の考え方にもとづく）。
5. 産業医サブロールは、運用事務（取込・メール配信など）を**既定では持たない**。

## 2. アカウントの発行・編集

### 2.1 入力項目

ログインアカウントの発行画面・編集画面に「サブロール」を追加する。

| 項目 | 仕様 |
|---|---|
| 表示条件 | 権限ロールで「企業担当者」を選んでいるときのみ有効。他のロールを選ぶと選択を自動的に「（なし）」へ戻す |
| 選択肢 | 「なし」「産業医」「人事」から1つ（単一選択） |
| 既定値 | なし |
| 各選択肢の補足表示 | 産業医＝「面談の承認・就業区分・面談記録・記名」、人事＝「取込・メール配信・対応区分・出力」 |
| 注意書き | 「医学的判断（承認・就業区分・面談記録・記名）は産業医のみが行えます。産業医はデータ取込とメール配信を行えません。」 |

### 2.2 検証ルール

- 権限ロールが企業担当者以外のとき、送信されたサブロール値は**無視して空にする**（画面で隠していても、直接送信された場合に備える）。
- サブロール値は既定の選択肢以外を受け付けない。不正値は空として扱う。

### 2.3 発行できる人

- サブロールの設定・変更は、**その企業担当者アカウントを発行・編集できる管理者**（既存仕様どおり：当社スタッフ・健保担当者・企業担当者のうち発行権限を持つ者）が行う。
- サブロールの付与によって、発行者本人より広い権限が対象アカウントに渡ることはない（サブロールは業務区分であり、閲覧範囲を広げない）。
- **本人は自分のサブロールを変更できない**（マイアカウントでの変更対象外。既存の「本人は権限を変更できない」原則と同じ）。

### 2.4 確認画面

- 発行・編集の確認画面に、権限ロールのバッジに続けてサブロールのバッジ（「産業医」／「人事」）を表示する。
- 確認から確定への再送信でサブロールの値を引き継ぐ。

### 2.5 変更時の記録

- 発行時の監査ログに「ロール＝企業担当者（産業医）」のようにサブロールを併記する。
- 編集時、サブロールが変わった場合は変更点一覧に「サブロール：なし → 産業医」の形で表示・記録する。

## 3. 一覧・検索・出力

### 3.1 アカウント一覧

- ロール列に、権限ロール名の下へサブロールのバッジを表示する（サブロールがある行のみ）。
- ロールの絞り込みに「企業担当者（産業医）」「企業担当者（人事）」を選択肢として追加する。

### 3.2 エクスポート（CSV）

- 出力項目に「サブロール」列を追加する（値は「産業医」「人事」または空）。

### 3.3 肩書きの表示

- 画面・確認・エラー表示・産業医面談内のメモ・帳票に出す担当者の肩書きは、
  サブロールがあれば「企業担当者（産業医）」のように併記する。サブロールがなければ従来どおり「企業担当者」。

---

## 4. 権限への影響

### 4.1 権限判定の単位

権限は、**権限ロールとサブロールを組み合わせた5区分**で判定する。

| 区分 | 表示名 |
|---|---|
| 当社スタッフ | 当社スタッフ |
| 健保担当者 | 健保担当者 |
| 企業担当者（サブロールなし） | 企業担当者 |
| 企業担当者（産業医） | 企業担当者（産業医） |
| 企業担当者（人事） | 企業担当者（人事） |

### 4.2 既定の業務範囲

サブロールなし・人事・当社スタッフ・健保担当者は、**同一の運用事務範囲**を既定とする。
産業医のみ範囲が異なる。

| 業務 | 人事／なし | 産業医 |
|---|---|---|
| マスタ（企業・事業所・部署・加入者）の**閲覧** | ○ | ○ |
| マスタの**登録・変更・削除・CSV取込** | ○ | ×（**閲覧のみ**） |
| 面談対象者一覧・健診受診管理の閲覧 | ○ | ○ |
| 面談対象の**承認・承認解除・面談不要（対象外）** | × | **○（固定）** |
| **就業区分**（通常勤務／就業制限／要休業）の判定 | × | **○（固定）** |
| **面談結果の記録** | × | **○（固定）** |
| 労基署提出書類への**記名・サイン** | × | **○（固定）** |
| **対応区分**（未判定／産業医判定済／要精査・加療指示 ほか）の設定 | ○ | ×（既定） |
| **データ取込**（労働時間・ストレスチェック・健診結果） | ○ | ×（既定） |
| **メール配信**（受診勧奨・ストレスチェック案内） | ○ | ×（既定） |
| 労基署報告の閲覧・帳票出力 | ○ | ○ |
| 疾患予測・アカウント管理・CSVダウンロード | ○ | ○ |

- 「固定」＝システム設定で変更できない。産業医サブロールのみが実行でき、他のどの区分にも付与できない。
- 「既定」＝運営会社（当社スタッフ）の機能制御設定で、区分ごとに利用可否を変更できる（第4.4）。

### 4.3 送信値の扱い（なりすまし防止）

- 医学的判断にあたる入力（承認・就業区分など）が、産業医サブロール**以外**から送信された場合、
  サーバ側でその値を**無視し、監査ログに「医学的判断の入力を無視」として記録**する。
- 対応区分の設定が、その機能を持たない区分から送信された場合も同様に無視・記録する。

### 4.4 機能制御との関係

- 運営会社（当社スタッフ）は、上記5区分 × 機能ごとに利用可否を切り替えられる（別機能）。
- ただし **固定の項目**（承認・就業区分・面談記録・記名）は切り替え対象外で、常に産業医サブロールのみ。
- **当社スタッフ**は、固定の項目を除き常に全機能を利用できる（機能制御の対象外）。

---

## 5. 統合画面（シェル）での扱い

- ログイン後の統合画面は、ログイン情報として権限ロール・サブロール・利用可能な機能の一覧を取得し、
  利用できないメニューを**非表示**にする。
- 産業医としてログインした場合、マスタ系メニューは「閲覧のみ」で表示し、取込・メール配信のメニューは表示しない。

---

## 6. 既存アカウントの移行

| 状況 | 移行後の扱い |
|---|---|
| 既存の企業担当者（サブロールの概念がなかった） | サブロール「なし」。業務範囲は人事と同じで従来どおり |
| 旧構成で「産業医」「人事」を**独立した権限ロール**として作っていた場合 | 権限ロールを「企業担当者」に付け替え、対応するサブロール（産業医／人事）を設定する。件数を移行ログに記録する |

移行後、産業医面談管理の各テーブル・機能制御の設定領域は空の状態で用意し、既定値で動作させる。

---

## 7. 監査ログ

サブロールに関して、少なくとも以下を記録する。

- アカウント発行時のサブロール（ロール名に併記）
- アカウント編集時のサブロール変更（前後の値）
- 医学的判断・対応区分の入力を、権限のない区分からの送信として無視したこと（送信元のロール区分・対象機能を含む）
- 既存ロールからサブロールへの移行件数（移行時）

| 箇所 | 追記内容 |
|---|---|
| 用語 | 「サブロール」＝企業担当者の業務区分（人事／産業医） |
| ロール定義 | 企業担当者に任意のサブロールを1つ持てること、付与できるのは企業担当者のみ |

| 一覧・検索・CSV | サブロール列・絞り込みの追加 |
| 権限判定 | ロール＋サブロールの5区分。医学的判断は産業医固定。既定範囲の表 |
| 監査ログ | サブロールの発行・変更・無視の記録 |

## 付録. 実装参照（実装依存・移植先では読み替える）

> 本番システムのデータ構造に合わせて設計し直すこと。現行モックアップでの持ち方を参考として記す。

- ログインアカウントに文字列カラム1つ（`sub_role`、既定は空文字。値は `doctor` / `hr` / 空）を追加している。
- 権限判定のキーは「権限ロール」＋（サブロールがあれば）「/サブロール」を連結した文字列（例 `company_user/doctor`）。
- 既存DBへは、カラム追加と、旧独立ロール（`doctor` / `hr`）から `company_user` ＋ `sub_role` への付け替えを冪等に行う移行処理を用意している。
