# HIA アカウント・マスタ管理

**画面は2種類、データベースは1つ**です。

| 画面 | URL | 利用者 |
| --- | --- | --- |
| HIA総合管理（緑） | `/km` | 当社スタッフ |
| HIA健保管理（青） | `/app` | 健保担当者・企業担当者 |

ログイン後は**権限に応じて自動で振り分けられます**。当社以外のアカウントで `/km` を開こうとすると
403 で拒否し、操作ログに記録します。

---

## 1. できること

### HIA総合管理（当社スタッフ）

1. 各健保・企業の**代表者アカウントの発行**
2. アカウント権限の**登録・編集・削除**
3. アカウントの**一覧確認**
4. **操作ログの管理**（HIA健保管理での操作ログも含む）
5. **マスタ情報の登録・閲覧・編集・削除**（企業・事業所・部署・加入者。全健保が対象）
   ／検査マスタの**区分番号**と「**区分番号マスタ**」
6. **機能制御**（権限ロール・サブロールごとに使える機能を切り替える）
7. **マイアカウント**（自分の利用者名・メールアドレス・パスワードの変更）

追加場所：サイドバー「AC設定」→「**アカウント管理**」「操作ログ管理」「**機能制御**」「**マイアカウント**」、
サイドバー「マスタ管理」→「**企業情報**」「**事業所情報**」「**部署情報**」「**加入者情報**」
（カードはサーバ連携のタグを付けて並べ、配色はセクションのテーマ色に合わせています）

マスタの4画面はHIA健保管理側と**同じ画面・同じデータ**です。当社スタッフは全健保を対象に操作でき、
企業を登録するときに健康保険組合を選びます。

原本にあったモック画面「アカウント設定」は、**「アカウント管理」に統合**しました。
原本の検索条件（健康保険組合名・所属企業名・ステータス）と列（健康保険組合名・所属企業名・登録日）を
アカウント管理側に取り込み、実データで動作します。

### HIA健保管理（健保担当者）

0. **産業医面談の管理**（対象者の抽出・健診受診管理・面談記録・労基署報告・メール配信・データ取込）
1. 健保担当者・企業担当者のアカウント**登録・編集・削除**
2. 企業情報の**登録・編集・削除**
3. 事業所情報の**登録・編集・削除**
4. 加入者情報の**登録・編集・削除**（CSV取込にも対応）
5. パスワードの再設定（**ログイン画面から本人が申請**）
6. **マイアカウント**（自分の利用者名・メールアドレス・パスワードの変更）

### HIA健保管理（企業担当者）

1. 企業担当者のアカウント**登録・編集・削除**（自社のみ）
2. 自社の企業情報の**編集**
3. 自社の事業所情報の**登録・編集・削除**
4. 自社の加入者情報の**登録・編集・削除**
5. パスワードの再設定（**ログイン画面から本人が申請**）

追加場所：サイドバーに「**マスタ**」を新設し、「企業情報」「事業所情報」「加入者情報」を配置。
「設定・サポート」→「アカウント管理」

サイドバーの横幅は **96px**（原本は88px）にしています。
サイドバーのラベルは、原本より読みやすくするため **11.5px / 太さ600（semibold）** にしています
（原本は11px / 400）。青シェルは未選択項目の文字色も少し濃くしました（白48%→68%）。

サイドバーの構成（上から）：健康診断／保健指導／**産業医面談**／インフル補助／分析／
**疾患予測**／**レセプト**／**マスタ**／設定サポート

原本のカードの変更：
- サイドバーに「**マスタ**」と「**レセプト**」を新設
- 「共通・基盤データ管理」は**廃止**し、カードを次のとおり振り分け
  - レセプト情報 UP・UP履歴：レセプト → **レセプト**
  - 接種実績 UP → **インフル補助**（申請一覧の次）
- 次のカードと画面は削除
  - 接種対象者情報 UP
  - 健診コースデータ UP
  - 各種フォーマット出力
  - 加盟企業情報 UP・加入者情報 UP（マスタの**一括インポート**で代替）

マスタ管理は本システムの3画面（企業情報・事業所情報・加入者情報）だけになりました。

移動したカードは、画面内の「戻る」ボタンも移動先のカテゴリへ戻るようにしています。

操作ログはHIA総合管理（当社）側でのみ確認します。

## 2. 権限ロール

| ロール | 閲覧範囲 | 登録できるロール |
| --- | --- | --- |
| 当社スタッフ | 全健保 | 当社スタッフ・健保担当者・企業担当者 |
| 健保担当者 | 自組合全体 | 健保担当者・企業担当者 |
| 企業担当者 | **担当する範囲**（企業・事業所・部署を跨いで指定） | **企業担当者のみ**（自分の担当範囲内） |

管理者（アカウント）は階層のどこにでも置けます。企業担当者は
「**担当する範囲**」として企業・事業所・部署を跨いで何件でも持てます
（→「6. データの構成」の階層図）。

### 企業担当者のサブロール（産業医面談管理）

企業担当者には、**サブロール**として「産業医」または「人事」を付けられます。
サブロールを付けるのは**企業担当者だけ**で、当社スタッフ・健保担当者には付きません
（画面に出さず、URLを直接呼んで送信した場合もサーバ側で無視します）。

| サブロール | 担う仕事 | 医学的判断 | 運用事務 |
| --- | --- | --- | --- |
| なし（通常） | マスタ・加入者情報などの通常業務 | × | ○ |
| **産業医** | 面談対象の承認・就業区分の判定・面談記録・報告書への記名 | **○** | × |
| **人事** | データ取込・メール配信・対応区分の管理・報告書の出力 | × | ○ |

閲覧範囲・担当する範囲の決め方はサブロールに関係なく企業担当者と同じです。
部署だけを担当する産業医（その部署の加入者だけを見る産業医）も作れます。

### 機能制御（ロール・サブロールごとに使える機能を切り替える）

HIA総合管理（当社スタッフ）の「AC設定」→「**機能制御**」で、
**権限ロール・サブロールごとに使える機能**を切り替えられます（`/settings/features`）。

| 区分 | 機能 |
| --- | --- |
| マスタ管理 | マスタの閲覧／マスタの登録・変更・削除／CSVの一括取込 |
| 産業医面談 | 面談対象者一覧／健診受診管理／**面談対象の承認・就業区分の判定**／**面談結果の記録**／**報告書への記名**／対応区分の設定／労基署報告／メール配信／データ取込 |
| そのほか | 疾患予測／アカウント管理／CSVのダウンロード |
| 設定・サポート | 設定・サポートを表示／お問い合わせ先／操作ログ管理／メール設定（**産業医は対象外**） |

- チェックを外した機能は、**画面・カード・ボタンを表示せず**、URLを直接呼び出した場合も
  **403で拒否して操作ログに記録**します（シェルのカードは `/api/me` の内容で出し入れします）
- **太字の4つ（医学的判断）は「固定」**です。面談対象の承認・就業区分の判定・面談結果の記録・
  報告書への記名は、労働安全衛生法の考え方にもとづき**産業医のみ**が行い、設定では変更できません
- CSVのダウンロードは、機能制御と**アカウントごとのダウンロード権限**の両方が「可」の場合だけ行えます
- **設定・サポートの4機能は企業担当者（産業医）の対象外**です。設定・サポートの管理は事務の仕事のため、
  表では「**対象外**」と表示し、切り替えられません（設定に関係なく利用不可）
- 変更は操作ログに残り、**各アカウントの次のアクセスから**適用されます。
  「初期値に戻す」で既定の状態（下の表）に戻ります

### 自分のアカウントの変更（マイアカウント）

どのロールでも「**マイアカウント**」（`/me`）で自分の情報を変更できます。
アカウント管理の一覧では、自分の行に「**自分の情報を編集**」ボタンが出ます。

| 変更できる | 変更できない（表示のみ） |
| --- | --- |
| 利用者名 | 権限ロール・サブロール |
| メールアドレス（ログインID） | 閲覧範囲・担当する範囲・対象の企業 |
| パスワード（現在のパスワードを確認して変更） | CSVのダウンロード権限・代表者区分 |

- **自分で権限を広げられないようにする**ため、権限に関わる項目は本人では変更できません
  （必要な場合は他の管理者へ依頼します）。URLを直接呼び出した場合もサーバ側で無視します
- メールアドレスを変えると、**変更前と変更後の両方**へ通知メールを送ります
- パスワードは12文字以上・英数字を含み、現在と同じものは設定できません。
  変更すると登録メールアドレスへ通知します（パスワードそのものはログに残しません）
- サポートログイン中は、誤操作を防ぐためマイアカウントを変更できません

### マスタの作成権限

| ロール | 健康保険組合 | 企業 | 事業所・部署 | 加入者 |
| --- | --- | --- | --- | --- |
| 当社スタッフ | **○** | **○** | **○** | ○ |
| 健保担当者 | × | **○**（自組合内） | **○**（自組合内） | ○（自組合内） |
| 企業担当者（なし・人事） | × | × | **○**（担当範囲内） | ○（担当範囲内） |
| 企業担当者（**産業医**） | × | × | ×（**閲覧のみ**） | ×（**閲覧のみ**） |

産業医は健診・面談に関する医学的判断を担うため、**マスタの登録・変更・削除は行いません**。
画面のボタンを表示しないだけでなく、URLを直接呼び出した場合もサーバ側で拒否し、
操作ログに記録します。

いずれもサーバ側で判定しており、URLを直接呼び出した場合も拒否して操作ログに記録します。
事業所は、自分が操作できる企業に対してだけ登録できます。

### 健康保険組合の登録

HIA総合管理の「健康保険組合管理」→「健康保険組合」（一覧）→「**新規作成**」→
**健康保険組合編集**の基本設定タブで登録します。

- 既存の「健康保険組合情報」カードの**保険者番号・保険者名称**をそのまま使います
- 基本設定タブの下部にあった「更新」ボタンを「**登録をやめて一覧を見る**」「**登録する**」に置き換えました
- 結果はボタンの左に表示されます（成功は緑、エラーは赤）
- 他のタブ（健診代行設定・保健指導設定・インフル設定）のボタンは原本のままです

**健康保険組合一覧はデータベースの内容を表示します。** 保険者番号・名称での検索も実データに対して動作します。
登録日・保険者番号・健康保険組合名・登録企業数は実際の値、それ以外の列（登録医療機関数・各権限・UL）は
まだデータベースに項目がないため「—」です。

当社スタッフのみ利用できます（健保担当者以下がAPIを直接呼んだ場合は403で拒否）。

- 保険者番号は各組合の番号を入力します（英数字とハイフン、20文字以内、重複不可）
- 名称も重複できません
- 一覧に企業数・加入者数・アカウント数を表示します
- **企業・加入者・アカウントが紐づいている組合は削除できません**（先にそれらを削除してください）

### 企業担当者の対象企業（複数選択）

企業担当者には**対象の企業を1社以上**割り当てます。グループ会社をまとめて担当する場合は複数選択できます。
選択した企業の加入者・事業所だけを閲覧・操作できます。

登録・編集画面の「**対象の企業**」カードで選びます。

- 企業コード・企業名で**検索**して絞り込めます
- チェックボックスで**複数選択**、「表示中をすべて選択」「選択を解除」も使えます
- 選択数が見出しに表示されます

企業担当者が別の企業担当者を登録する場合、**選べる企業は自分の対象企業だけ**です。
URLを直接呼び出して範囲外の企業を混ぜた場合もサーバ側で拒否し、操作ログに記録します。

**自分より広い権限は付与できません。** 選択肢に表示せず、URLを直接呼び出した場合も
サーバ側で拒否して操作ログに記録します。

自分自身のアカウントは編集・削除・無効化できません（自分で権限を広げられないようにするため）。

### 登録前に閲覧範囲を確認します

アカウントの登録・編集の前に、**そのアカウントが実際に閲覧できる加入者**を表示します。

- 件数・対象企業数・対象事業所数
- 企業別・事業所別の内訳
- 実際の加入者一覧（先頭20件）
- 閲覧範囲が自社を超える場合は警告

確認のチェックを入れないと登録・保存できません（サーバ側でも検証）。
登録内容と閲覧対象件数は操作ログに記録されます。

## 3. 起動する

### Windows

```
run.bat をダブルクリック
```

初回はデータベースを作成し、**当社スタッフのアカウント1件**を作成します。
表示されるログインIDとパスワードを控えてください（再表示できません）。

### 手動で起動する

```
pip install -r requirements.txt
python seed.py                                  # 初回のみ
python -m waitress --host=0.0.0.0 --port=8000 app:app
```

### ブラウザから開く

- 当社スタッフ　　`http://10.0.105.122:8000/km`
- 健保・企業　　　`http://10.0.105.122:8000/app`
- ログイン　　　　`http://10.0.105.122:8000/login`

ファイアウォールで受信を許可する場合：

```
netsh advfirewall firewall add rule name="HIA 8000" dir=in action=allow protocol=TCP localport=8000
```

### 旧バージョンから更新した場合（重要）

すでに `hia.db` がある状態でファイルを差し替えると、テーブルの列が足りずエラーになります
（`table audit_log has no column named shell` / `no such column: reset_token` など）。
**データを保持したまま移行できます。**

```
migrate.bat をダブルクリック
```

またはコマンドで：

```
python migrate.py
```

`run.bat` は起動時に自動で移行を確認するので、通常は `run.bat` を実行するだけで済みます。
移行前に `hia.db.bak` としてバックアップを作成します。何度実行しても安全です。

移行内容：

| 対象 | 内容 |
| --- | --- |
| 部署 → 事業所 | `department` を `office` へ移行し、加入者の紐づけを引き継ぎ |
| 企業・部署の追加項目 | 被保険者証記号・郵便番号・担当メールアドレス・部署名フリガナの列を追加 |
| アカウントの対象企業 | `account_company` を作成し、既存の所属企業を移行（1社のまま引き継ぎ） |
| アカウント | `is_primary` `reset_token` などの列を追加 |
| ロール名 | `kenpo_admin` → 健保担当者、`company_admin` → 企業担当者へ変換 |
| 企業 | カナ・電話番号・所在地の列を追加 |
| 操作ログ | `shell`（画面）などの列を追加。**既存のログは保持** |
| 採番キー | 部署用から事業所用へ付け替え |

初期状態に戻す場合は `hia.db` を削除して `run.bat` を実行してください（**登録済みデータは消えます**）。

### 管理者でログインできないとき（更新した場合）

**すでに `hia.db` がある状態で新しいZIPに入れ替えると、管理者アカウントは追加されません。**
`seed.py` は既存データがあると初期投入をスキップするためです。

次のどれかで解決できます。

| 方法 | 手順 |
| --- | --- |
| **`set_admin.bat` を実行（おすすめ）** | ダブルクリックするだけ。管理者がいなければ追加し、いればパスワードを再設定します |
| `seed.py` を実行 | 既存データがあっても、**当社スタッフのアカウントが無ければ追加**します |
| `admin.bat` を実行 | 登録済みのアカウント一覧を表示し、ログインIDを指定してパスワードを再設定します |

`set_admin.bat` の中身を書き換えると、別のIDやパスワードにできます。

```bat
set HIA_ADMIN_EMAIL=Jun.Ito@kusurinomadoguchi.co.jp
set HIA_ADMIN_NAME=伊藤 惇
set HIA_ADMIN_PASSWORD=EPARK1234567890-
```

- ログインIDは**大文字小文字を区別しません**（前後の空白も無視します）
- 旧バージョンの `staff@example.local` は残ります。不要なら一覧から削除してください
- ログイン後は「設定・サポート → パスワード変更」で必ず変更してください

### ログインできないとき

当社スタッフのパスワードを忘れた場合は `force_reset.bat`（または `python reset_admin.py --admin`）で
再設定できます。健保担当者・企業担当者はログイン画面の「パスワードをお忘れの方」から本人で再設定できます。

## 3.5 サポートログイン（当社スタッフ）

当社スタッフが、健康保険組合の画面（HIA健保管理）に入ってサポートできます。

### 使い方

1. HIA総合管理 → **健保管理 → 健康保険組合一覧**
2. 対象の行の「**サポートログイン**」を押す
3. 確認のダイアログで内容を確認して進む
4. HIA健保管理（青い画面）が開き、その健保の担当者と同じ範囲で操作できます
5. ヘッダーのタグにある「**終了**」で、サポートを終了して当社の画面に戻ります

サポート中はヘッダーに表示が出ます。

```
┌─ HIA健保管理 ──────────────────────────────────────────────────┐
│              ┌──────────────────────────┐                      │
│              │! サポートログイン中       │ [KM] 当社スタッフ    │
│              │  6139166 ひかり健康保険組合│      （サポート）    │
│              │                    [終了] │      [ログアウト]    │
│              └──────────────────────────┘                      │
└════════════════════════════════════════════════════════════════┘  ← 赤茶の帯
```

ヘッダーの下にも赤茶色の線が入り、サポート中であることが常に分かります。

### 安全のための決まり

- **当社スタッフのみ**が使えます（他のロールからの要求は拒否し、操作ログに記録します）
- サポート中は**ヘッダーに赤茶色のタグが出続けます**（すべての画面で表示）
  ヘッダーの下にも同色の線が入ります
- 操作ログには「**誰が**」「**どの健保に入って**」行ったかを両方残します
  - 実行者：当社スタッフのメールアドレスとロール
  - 対象：その健保のID
  - 備考：`サポートログイン中（○○健康保険組合）`
- 開始と終了もそれぞれ操作ログに記録します
- サポート中に HIA総合管理（`/km`）を開くと、**サポートを終了して**戻ります
- サポート中の権限は、その健保の担当者と同じです（健保をまたいだ閲覧はできません）

## 3.6 疾患予測（健診結果から個人ごとの将来リスクを出す）

サイドバーに「**疾患予測**」を追加しました。
**健診結果を取込むことで、加入者ひとりずつの3年後の生活習慣病リスク**を出します。
保健指導の優先度づけにお使いください。

### 3つの画面

| カード | 内容 |
| --- | --- |
| 予測結果一覧 | **加入者ごと**のリスクスコアと保健指導優先度。絞り込みとCSV出力 |
| 健診結果の連携 | 予約管理システムからのXML取込（バッチ）と履歴 |
| NSIPS連携状況 | 調剤システムとのAPI連携（服薬状況は属性区分の傾向として反映） |


### 流れ

```
① 健診結果のXMLを取込む（予約管理システムからのバッチ）
   → 被保険者証の記号・番号・枝番で加入者マスタと突合
   → 検査値から判定（基準内／要注意／要医療）を求め、個人ごとに保存
② 「予測を実行する」を押す（既定は3年後）
   → 健診結果のある加入者について、8疾病それぞれのスコアを算出
③ 一覧で確認・絞り込み・CSV出力／「内訳」で1人ずつの詳細を確認
```

### 2つの見かた（切り替えできます）

一覧の上部のタブで、**個人単位**と**属性単位**を行き来できます。どちらもグラフ付きです。

| タブ | 内容 | グラフ |
| --- | --- | --- |
| **個人単位** | 加入者ひとりずつの結果 | リスク区分の内訳（積み上げ）／リスクスコアの分布（10点刻み） |
| **属性単位** | 年代・性別・疾病・企業ごとにまとめた結果 | 年代×性別の高リスク者数（縦棒）／疾病ごとの高リスク者数（横棒）／年代ごとの平均スコア（横棒）／企業ごとの高リスク者数（横棒） |

属性単位では、グラフの下に「年代・性別ごとの内訳」「疾病ごとの内訳」の表も出ます。

- 属性単位の集計は、**その人でいちばん高い疾病のスコア**を代表値として使います
  （疾病ごとの内訳だけは8疾病それぞれで集計します）
- グラフは**SVGで描いており、外部ライブラリを使っていません**（社内LANでも表示できます）
- 絞り込み条件はタブを切り替えても保持されます

### 一覧の見かた

加入者1行につき、**その人で最もリスクの高い疾病**を表示します。
疾病を選ぶと、その疾病でのスコア順に並び替わります。

```
被保険者証番号  氏名     企業名        年代 性別 最もリスクの高い疾病  スコア  区分
9001-0        見本 一郎  見本商事株式会社  60代 男   高血圧性疾患        100.0   高 A
9003-0        見本 二郎  見本商事株式会社  40代 男   心血管疾患           84.7   高 A
```

「内訳」を押すと、その加入者の**健診結果の判定（検査値つき）**と
**8疾病それぞれのスコア**が確認できます。

### スコアの決まり方

| 入力 | 反映のしかた |
| --- | --- |
| **健診結果（必須）** | その人の判定。要医療は重く、要注意は軽めに加点 |
| 年代・性別 | 基礎値 |
| NSIPS（任意） | 属性区分の服薬状況（長期処方・服薬中断）を加点 |
| 予測年数 | 年数が長いほど少し高くなる |

- リスク区分：60以上=高（優先度A）／35以上=中（B）／それ未満=低（C）
- 対象疾病は8大生活習慣病（糖尿病・高血圧性疾患・脂質異常症・心血管疾患・
  脳血管疾患・腎疾患・肝疾患・悪性新生物）
- **健診結果がない加入者は予測しません**

### 設定はサーバー側で行います

set HIA_RISK_MATCH_RULE=cert
set HIA_RISK_HORIZON=3

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `HIA_HITACHI_ENDPOINT` | 空 | 日立APIの接続先。**設定すると契約モデルに切り替わります** |
| `HIA_HITACHI_KEY` | 空 | 日立APIの認証キー |
| `HIA_KENSHIN_ENDPOINT` | 空 | 予約管理システムの接続先 |
| `HIA_KENSHIN_TIME` | `02:00` | 健診バッチの実行時刻（記録用） |
| `HIA_NSIPS_ENDPOINT` | 空 | 調剤システムの接続先 |
| `HIA_NSIPS_MODE` | `batch` | `batch`（日次）または `realtime` |
| `HIA_RISK_MATCH_RULE` | `cert` | 突合方法。`cert`（被保険者証の記号・番号・枝番）または `anonid` |
| `HIA_RISK_HORIZON` | `3` | 既定の予測年数 |

未設定の場合は次のように出て、**社内の簡易ロジックで試算**します。

```

```

### 判定グループ（複合した検査からまとめて判定）

空腹時血糖のように、**複数の検査値から1つの判定を出す**必要がある項目に対応しました。
検査マスタの検査項目に対応するマスタなので、**HIA総合管理のマスタ管理**に置いています。

```
マスタ管理 ┬ 検査マスタ
           ├ 判定グループ   ← ここ
           └ OID結果マスタ
```

- **当社スタッフのみ**が変更できます（健保担当者・企業担当者はアクセスを拒否します）
- 全健保に共通で適用され、各健保が健診結果を取込むときにこのルールで判定されます

**初期登録（6グループ）**

| グループ | 検査項目 | 判定方法 |
| --- | --- | --- |
| 血圧 | 収縮期血圧・拡張期血圧 | 最も重い判定を採用 |
| 血糖 | 空腹時血糖・HbA1c（NGSP） | 最も重い判定を採用 |
| 脂質 | LDL・HDL・中性脂肪 | 最も重い判定を採用 |
| 肝機能 | AST・ALT・γ-GT | 最も重い判定を採用 |
| BMI | BMI | — |
| 尿蛋白 | 尿蛋白（記号） | — |

**判定方法は3つから選べます**

| 方法 | 動き | 使いどころ |
| --- | --- | --- |
| **最も重い判定を採用**（既定） | どれか1つでも要医療なら要医療 | 血圧・血糖など、いずれかが基準を超えたら所見ありとする項目 |
| すべて該当したときだけ判定 | 全項目がそろって初めて判定 | 複数の検査をあわせて判断する項目 |
| 上から順に最初に判定できた項目 | 優先する検査があればそれを使う | 代替検査がある項目 |

**項目ごとの設定**

| 設定 | 内容 |
| --- | --- |
| 検査項目名 | 必須。項目コードが空欄のときはこの名前で照合します |
| 項目コード | 健診XMLの検査項目コード |
| 判定の向き | 高いほど悪い／**低いほど悪い**（HDLなど）／記号（−・±・＋） |
| 要注意（以上）・要医療（以上） | しきい値。「記号」の場合は不要 |
| 単位 | 表示用 |

- グループの追加・編集・削除ができ、**変更後に健診結果を取込み直すと新しいルールで判定**されます
- 保存内容は操作ログに記録します
- 判定結果は疾患予測のスコアにも反映されます（要医療は重く、要注意は軽めに加点）

動作の確認例（血圧を「すべて該当したときだけ判定」に変更）

| 検査値 | 最も重い判定を採用 | すべて該当したときだけ |
| --- | --- | --- |
| 収縮期166／拡張期99 | 要医療 | 要医療 |
| 収縮期143／拡張期86 | **要医療** | **要注意** |
| 収縮期133／拡張期80 | **要注意** | **基準内** |

| --- | --- | --- |

- 判定は特定健診の保健指導判定値・受診勧奨判定値を目安にしています

### 個人情報と医療的判断の取り扱い

- 予測結果は**加入者ごと**のため、画面とCSVに氏名・被保険者証番号が含まれます。

### 面談候補の自動抽出

一覧を開くたびに、次の条件で面談候補を抽出し、抽出理由を付けます（複数該当は併記）。

| 条件 | 判定 | 抽出理由の例 |
| --- | --- | --- |

### 判定区分（学会区分 A〜E）

総合判定は**日本人間ドック・予防医療学会の判定区分（2026年4月1日改定）**に準拠します。

| 区分 | 意味 | 扱い |
| --- | --- | --- |
| A | 異常なし | |
| B | 軽度異常 | |
| C | 要再検査・生活改善 | **有所見**（面談候補） |
| D | 要精密検査・治療 | **有所見**（面談候補） |
| E | 治療中 | **有所見**（面談候補） |

旧表記（異常なし・要注意・要医療・要精密検査 など）のデータは、
取込時・表示時に**自動で新区分へ読み替え**ます。

### データ取込（人事）

| 取込 | 内容 | 面談候補への連動 |
| --- | --- | --- |
| 健診結果CSV | 受診年度・健診区分・受診日・総合判定・産業医所見 | C判定以上を抽出 |
| 労働時間CSV | 対象年月・時間外労働時間・休日労働時間 | 月80／100時間超を抽出 |
| ストレスチェックCSV | 実施年度・受検日・合計点・高ストレス者・面接指導の申出 | 高ストレス者を抽出 |

- テンプレートCSV（記入例つき・Shift_JIS）を各取込の右上からダウンロードできます
- 加入者との突合は「**社員コード → 被保険者証番号 → 氏名 → 加入者ID**」の順に行います。

## 4. パスワードの取り扱いと案内メール

**アカウントを登録すると、そのメールアドレス宛に案内メールが自動送信されます。**
メールにはパスワード設定用のURLが記載され、**ご本人がパスワードを設定**するとログインできるようになります。

- 初回パスワードは発行しません。管理者がパスワードを決めることは一度もありません。
- パスワードは復元できない形式（ハッシュ）で保存します。管理者も内容を見られません。
- 案内リンクの有効期限は72時間。1回だけ使用できます。

### メールが使えない場合のパスワード設定

SMTPを設定していない環境でも、次の2つの方法でパスワードを設定できます。
アカウント一覧の各行にボタンがあります。

| ボタン | 内容 |
| --- | --- |
| **案内リンク** | パスワード設定用のリンクを画面に表示します。社内チャットや口頭でご本人へ伝えてください |
| **PW設定** | 管理者がその場でパスワードを設定します（自動生成／手入力） |

**案内リンクの表示**

- 期限切れ・未発行の場合は、その場で新しいリンクを発行します
- リンクと、そのまま送れる**文例**をコピーできます
- ご本人が開いて設定すると、そのリンクは使えなくなります（1回だけ有効）

**管理者が設定する場合**

- 「自動で作る」を選ぶと、読み間違えにくい14文字のパスワードを作り、**1度だけ表示**します
- 手入力もできます（12文字以上・英字と数字を含む）
- 設定するとアカウントは「有効」になり、未使用の案内リンクは無効になります
- 管理者もパスワードを知っている状態になるため、**ご本人にログイン後の変更を依頼**してください
- 発行・表示・設定はすべて操作ログに記録します（パスワードそのものは記録しません）

### メール送信の設定

社内のSMTPサーバーを環境変数で指定してください（`run.bat` に記入欄があります）。

| 変数 | 内容 |
| --- | --- |
| `HIA_SMTP_HOST` | SMTPサーバー（**未設定だと送信されません**） |
| `HIA_SMTP_PORT` | ポート（既定 25） |
| `HIA_SMTP_FROM` | 送信元アドレス |
| `HIA_SMTP_USER` / `HIA_SMTP_PASS` | 認証が必要な場合 |
| `HIA_BASE_URL` | **メールに載せるURLの基準**。例 `http://10.0.105.122:8000` |

`HIA_BASE_URL` は必ず設定してください。未設定の場合、サーバー上で `localhost` からアクセスして
登録すると、受信者が開けない `http://localhost:8000/...` というURLが送られてしまいます。

送信内容は `outbox/` フォルダにも控えとして保存されます。
**SMTPが未設定のときは送信されず、控えの保存のみ**となります。その場合は登録完了画面に
「送信できませんでした」と表示され、画面のリンクをご本人へお渡しする運用になります。

### 権限を変更したとき

アカウントの権限を保存すると、**ご本人宛に設定変更のお知らせメールを自動送信**します。

保存ボタンを押すと確認モーダルが開き、送信先と**送信されるメールの内容**を確認できます。
「キャンセル」で戻れば保存もメール送信も行いません。

メールに記載する内容：変更された項目の前後の値／変更後に閲覧できる加入者の件数。
**パスワードは含みません。** 変更点がない場合はメールを送信しません。

### パスワードを忘れたとき

1. 本人がログイン画面の**「パスワードをお忘れの方」**からメールアドレスを入力
2. **再設定用のURLがメールで届く**（有効期限2時間・1回のみ）
3. 本人が新しいパスワードを設定

申請時、入力されたアドレスが登録済みかどうかは画面に表示しません。

**管理者の操作は不要です。** 申請から再設定まで、ご本人の操作だけで完了します。
メールが届かない場合は、迷惑メールフォルダの確認と、`HIA_SMTP_HOST` / `HIA_BASE_URL` の
設定を確認してください。

### すぐにログインを止めたいとき

編集ページの「アカウントの状態」にある「**無効化する**」を使います。
ログインできない状態になりますが、パスワードは保持されるため「有効化する」でそのまま復帰できます。

| 操作 | 場所 | ログイン | 元に戻せるか | 用途 |
| --- | --- | --- | --- | --- |
| パスワード再設定 | ログイン画面（本人が申請） | できる | — | 忘れた／変更したい |
| 無効化 | 編集ページ | **できない** | **有効化で戻せる** | 退職・不正利用の疑い・一時停止 |
| 削除 | 一覧 | **できない** | **戻せない** | 利用終了 |
| 完全削除 | 一覧（削除済みの行） | **できない** | **戻せない** | 同じアドレスを使い直すとき |

**アカウントの復元はできません。** 一時的に止めたい場合は「削除」ではなく「無効化」を使ってください。
無効化ならパスワードを保持したまま、あとで「有効化」で元に戻せます。

削除したアカウントのメールアドレスは、そのままでは再登録できません（同じアドレスは登録できない仕組みのため）。
再登録が必要な場合は、一覧の削除済みの行から「**完全削除**」を実行してください。
完全削除しても**操作ログは残ります**。

### 本人と家族の区別（重要）

**本人と家族は同じ被保険者証番号で、枝番が異なります。**
そのため加入者の一意判定は「健保＋被保険者証記号＋被保険者証番号＋**枝番**」で行います。

| 被保険者証 | 続柄 | 氏名 |
| --- | --- | --- |
| 記号1000・番号9001・枝番0 | 本人 | 伊藤博文 |
| 記号1000・番号9001・枝番1 | 妻 | 伊藤梅子 |

一覧では「9001-1」のように枝番を添えて表示します。

### 加入者一覧から紐づける（もっとも手軽な方法）

加入者情報の一覧には**企業名・事業所名・部署名**の列があります。
この一覧で対象を選んで、そのまま紐づけられます。

```
検索： 被保険者証番号[    ] 氏名[未紐づけ] 企業名[  ] 事業所名[  ] 部署名[  ] 紐づけ[▼]

加入者一覧  [選択した2件を紐づける][検索結果すべて（12件）を紐づける][コードで紐づける]…
┌──┬────────┬──────────┬───┬─────────┬────────┬───────┬──────┐
│☑ │ 6001   │ 未紐づけ01 │ … │ 未紐づけ  │ 未設定  │ 未設定 │編集…│
│☑ │ 6002   │ 未紐づけ02 │ … │ 未紐づけ  │ 未設定  │ 未設定 │編集…│
└──┴────────┴──────────┴───┴─────────┴────────┴───────┴──────┘
        ↓ ボタン
┌─ 企業・事業所・部署を紐づける ────────────────────┐
│ 選択した 2件 の加入者を紐づけます。                  │
│ 企業 [必須] [456　光通信株式会社            ▼]      │
│ 事業所        [8718　本社                   ▼]      │
│ 部署          [02　営業部                   ▼]      │
│              [キャンセル][この内容で紐づける]        │
└──────────────────────────────────────────────────┘
```

対象の選び方は3通りです。

| 方法 | 動き |
| --- | --- |
| 行のチェック | 個別に選ぶ（ボタンに件数が出ます） |
| 見出しのチェック | **表示中をすべて選択** |
| 「検索結果すべて（N件）を紐づける」 | **絞り込んだ条件に一致する全件**が対象（読み込んでいない分も含む） |

- 企業を選ぶとその企業の事業所、事業所を選ぶとその部署だけが候補になります
- 事業所・部署は「未設定」のままでも紐づけられます
- 「検索結果すべて」を選んだときは、モーダルに**絞り込み条件**を表示します
  （例：`条件：氏名「未紐づけ」`）
- 紐づけたあとは一覧を読み直し、企業名・事業所名・部署名の列に反映されます
- 実行内容（対象件数・紐づけ先・絞り込み条件）は操作ログに記録します

### 加入者情報のコードで紐づける（取込したコードを使う）

取込した加入者情報には「事業所（企業）コード」「所属コード」が入っています。
このコードを加入者に保存しておき、**あとからまとめて紐づけられます**。

**加入者を先に取り込んでも構いません。** 企業・事業所を後で登録すれば、コードで自動的に結びつきます。

```
① 加入者情報だけを取り込む（企業は未登録）
   → 7件すべて未紐づけ。ただしコード（456 / 8718 など）は保存される
② あとから企業・事業所を登録する
③ 加入者一覧の「コードで紐づける」を開く
   → 紐づけできる 7件
   ┌────────────────────────────────────────────────────────────┐
   │ ☑ 9001 伊藤博文 企業456 光通信株式会社  所属8718 本社        │
   │ ☑ 9002 山田花子 企業456 光通信株式会社  所属8719 大阪支社    │
   └────────────────────────────────────────────────────────────┘
                        [一覧に戻る][選択した7件を紐づける]
④ 実行 → 「加入者情報のコードで 7 件を紐づけました。」
```

- 開く場所：**加入者一覧の「コードで紐づける」ボタン**／紐づけページに出る案内
- 一件ずつチェックを外して、対象を選ぶこともできます
- コードはあるが一致する企業・事業所がない加入者は「**確認が必要な加入者**」として
  理由付きで別に表示します（例：「企業コード「456」に一致する企業がありません」）
- 企業・事業所は「先方が管理する番号」でも「当社内部コード」でも照合します
- 実行内容は操作ログに記録します

### 一覧の表示件数と画面の高さ

マスタの一覧（企業情報・事業所情報・加入者情報）は、**最初に30件**を表示し、
表を下までスクロールすると**続きを30件ずつ読み込みます**。

- 検索条件を保ったまま読み込みます
- すべて表示し終わると「全 N 件を表示しました」と表示します
- 表の**見出し行は固定**され、スクロールしても列名が常に見えます

**画面の高さは固定です。** 画面の高さいっぱいに収まり、表の中だけがスクロールします。
行を読み込んでも、検索で件数が変わっても、**画面全体の高さは動きません**。

| 画面の高さ | 一覧の枠 | 表の領域 |
| --- | --- | --- |
| 700px | 526px | 243px |
| 900px | 726px | 443px |
| 1100px | 926px | 643px |

ウィンドウの大きさを変えると自動で合わせ直します。
登録・編集画面は内容に応じた高さのままです（固定しません）。

あわせて、原本のシェルに入っていた高さの固定値（`min-height:1080px`）を画面の高さ基準に変更しました。
これにより、1080pxより小さい画面でも余分な余白やスクロールが出なくなりました。

読み込みは `/companies/rows`・`/offices/rows`・`/members/rows` が行の断片を返す形で行っています。
アカウント一覧・操作ログ・健康保険組合一覧はこれまでどおり一度に表示します。

取込用のCSVフォーマット（見出し行と記入例）は、**一括インポートのモーダル内**の
「フォーマットをダウンロード」から取得します。Excelでそのまま開けるよう Shift_JIS で出力します。
企業情報のボタンは企業を登録できるロール（当社スタッフ・健保担当者）にだけ表示されます。
表の列は幅を指定しており、1つの列だけが極端に広がることはありません。操作列は150px以上を確保しています。

「アカウント登録」ボタンは一覧の見出しの右端にあります。

自分が管理できるアカウントに限られます。健保担当者は当社スタッフのアカウントに、
企業担当者は他社や健保担当者のアカウントに対して操作できません。
登録・変更・削除・リンク発行・申請・ブロックはすべて操作ログに記録されます。

## 6. データの構成

### 管理する階層

```
システム
└─ 健康保険組合（保険者番号・名称）
   └─ 企業（事業所（企業）コード）
      └─ 事業所（所属コード）
         └─ 部署（部署コード）
            ├─ 管理者（担当部署だけを見るアカウント）
            │    └─ サブロール：なし／産業医／人事（企業担当者のみ）
            └─ 加入者
```

| 階層 | テーブル | コード | 画面 |
| --- | --- | --- | --- |
| 健康保険組合 | `kenpo` | 保険者番号（手入力） | HIA総合管理 |
| 企業 | `company` | 事業所（企業）コード（自動採番・4桁） | マスタ → 企業情報 |
| 事業所 | `office` | 所属コード（自動採番・3桁） | マスタ → 事業所情報 |
| 部署 | `department` | 部署コード（自動採番・3桁） | マスタ → 部署情報 |
| 加入者 | `member` | 加入者ID（自動採番・8桁） | マスタ → 加入者情報 |
| 管理者 | `account` | — | 設定・サポート → アカウント管理 |

- **加入者は事業所・部署が未設定でも登録できます**（あとから紐づけられます）
- 部署は事業所ごとに登録し、同じ事業所内で名称・コードが重複できません
- 加入者・管理者が紐づいている部署は削除できません
- 管理者は「**担当する範囲**」として企業・事業所・部署を跨いで持てます。
  企業担当者には**サブロール（産業医・人事）**を付けられます（→「2. 権限ロール」）

### 産業医面談管理のテーブル

加入者（`member`）を軸に、健診・労働時間・ストレスチェック・面談の情報を持ちます。
加入者マスタは共通で、名簿を二重に持ちません。

| テーブル | 内容 |
| --- | --- |
| `oh_kenshin` / `oh_kenshin_item` | 健診の受診記録（総合判定A〜E）と結果票の明細（前年比較用） |
| `oh_overtime` | 月次の時間外労働・休日労働 |
| `oh_stress` | ストレスチェックの点数・高ストレス者判定・面接指導の申出 |
| `oh_candidate` | 面談候補（抽出理由・ステータス・就業区分・対応区分・勧奨回数） |

### 管理者の担当範囲（企業・事業所・部署を跨げます）

アカウント登録で企業担当者を選ぶと、**企業・事業所・部署をまとめて何件でも**担当させられます。
企業を跨いだ指定もできます。

```
┌─ 対象企業 ────────────────────────────────────┐
│ ▸ 0001 光通信株式会社   ▸ 0002 ひかり物流株式会社  │
└──────────────────────────────────────────────┘
┌─ 担当する事業所・部署（任意）────────────────────┐
│ 事業所 2件選択中          │ 部署 1件選択中         │
│ ☑ 002 光通信／大阪支社     │ ☑ 002 光通信／本社／営業部│
│ ☑ 001 ひかり物流／東日本   │ ☐ 001 光通信／本社／総務部│
└──────────────────────────────────────────────┘
```

| 閲覧範囲 | 見える加入者 |
| --- | --- |
| 全健保 | すべて（当社スタッフ） |
| 自組合全体 | その健康保険組合のすべて（健保担当者） |
| **担当する範囲** | **担当に指定した企業・事業所・部署の加入者すべて**（企業担当者） |

- 企業を指定すると、その配下の事業所・部署すべてが対象になります
- **企業を指定せず、事業所や部署だけ**を担当させることもできます
- 指定は企業・事業所・部署を混在でき、**企業を跨いで**選べます
- 加入者は「担当した企業・事業所・部署のどれかに当てはまる」ものが見えます
- 一覧・登録・編集・紐づけのすべてで同じ範囲が適用されます

担当範囲は `account_scope` テーブルで管理します（旧バージョンの対象企業は移行時に引き継がれます）。

```
健康保険組合
  └─ 企業（企業コードを自動採番）
       └─ 事業所（事業所コードを自動採番）
            └─ 加入者

アカウント ──（複数）── 企業     ※ account_company テーブル
```

- コードはすべて**システムが採番**します。手入力・転記は不要です。
- 加入者のCSV取込は**事業所名**で指定し、システムが事業所コードへ変換します。
- 取込は「アップロード → 内容とエラーの確認 → 確定」の3手順で、**エラーがある間は確定できません**。
- 紐づきのあるデータは削除できません（事業所・加入者・アカウントが残っている企業など）。

### 一括インポート（企業・事業所・加入者）

3つのマスタすべてで一括インポートに対応しています。各一覧画面の「**一括インポート**」ボタンから

- コード（企業コード・事業所コード）は確定時にシステムが自動採番します

## 8-1. 全画面に適用した共通ルール

**一覧テーブル 列幅の標準（項目単位のマスタ）**
同じ項目はどの画面でも同じ幅にし、画面ごとの個別指定はしません。CSSのクラスとして
`static/app.css`・両シェルに置いてあり、新しい画面でもこのクラスを使います。

| `.col-date` | 100px | 日付 |
| `.col-dt` | 150px | 日時（日付＋時刻。最終ログイン・配信日時など） |
| `.col-year` | 140px | 年度 |
| `.col-name` | 120px | 氏名 |
| `.col-user` | 160px | 利用者名（アカウント名） |

| `.col-mail` | 220px | メールアドレス |
| `.col-num` | 120px | 各種番号・ID・コード |
| `.col-status` | 130px | ステータス・判定・案内状況・支援区分など |
| `.col-money` | 100px | 金額 |

画面に収まらないときは**列幅を変えず、文字を「…」で省略**します
（`table td{overflow:hidden;text-overflow:ellipsis}` を共通で当てています）。
省略された文字は**マウスオーバーで全文**が出るように `title` を付けています。
見出し（th）は省略せず、長い見出しは `<br>` で2行にしています
（例：被保険者<br>記号-番号、最終ログイン）。
ボタンが並ぶ操作セル（`td.ops`／`td.op-cell`）は、収まらないときは折り返します
（例：メールテンプレート一覧の「詳細・編集・複製・削除」は2行になります）。
操作列はこれまで280pxでしたが、標準の**260px**に変更しました。

**テキスト・タイポグラフィの共通ルール**
意味・役割ごとに大きさと太さを決め、画面ごとには変えません。

| 用途 | サイズ | 太さ |
|---|---|---|
| h1（ページタイトル） | 24px | Bold |
| h2（セクション） | 18px | Bold |
| h3（サブセクション） | 16px | Bold |
| h4（小項目） | 14px | 300（細字） |
| 本文 p ／ テーブル ／ 入力欄 ／ ラベル | 14px | Normal |
| ボタン | 14px | Bold |
| 補足・注釈（`.hint`／`.note`／`.page-desc` など） | 12px | Normal |

基本文字色 **#333333**、行間 1.6。画面ごとに書かれていた `font-size`／`font-weight`／
`line-height` のインライン指定は、h1〜h4・p・label・button から**407か所外しました**。

**表の中の文字**は `table th` を14px・太字、`table td` を14px・標準にそろえました
（画面ごとに13px／12px／11.5pxになっていた指定をやめています）。
**ボタンの文字**は要素の種類にかかわらず14px・太字です。`<button>` だけでなく、
見た目がボタンのリンク（`a.btn-sm`／`a.btn-back` など）や `input[type=submit]` も
同じ大きさになります。
**ハブカードの見出し**は、タイトルを `h3`（18px 太字）、説明を `h4`（14px・太さ300）に
そろえました。
ヘッダーのサービス名は「ロゴ」なのでページタイトルの対象外とし、両シェルで
18px・太さ500・#626262にそろえています。

**フォントを全画面で統一しました。**
`'Zen Kaku Gothic New' → 'Noto Sans JP' → 端末の日本語書体` の順で、シェル・iframe内の画面・

機能制御の設定画面に「**HIA健保管理**」のグループ（6機能）を追加しました。
健康診断 代行管理／特定保健指導／インフルエンザ補助／レセプト情報／加入者情報の変更（健保側）／

**上段の「戻る」で1つ前の画面に戻れるようにしました。**
本システムの画面（アカウント管理・マスタ・産業医面談など）はシェルの中に埋め込んで表示して
いるため、上段の「← 戻る」は今までカードの一覧まで一気に戻っていました。これを、
**埋め込んだ画面の中で進んでいれば、まずその中で1つ前の画面へ戻る**ようにしました
（例：アカウント一覧 → 編集 → 「戻る」→ アカウント一覧）。「中止する」を押す必要はありません。
最初の画面で押した場合だけ、これまでどおりカードの一覧へ戻ります。
しくみは `SYS.watch()` で埋め込み画面の移動回数を数え、`sysBack()` が
`history.back()`（回数が1以上のとき）と画面の切り替えを使い分けます。緑・青の両シェルに入れました。

**当社スタッフは機能制御の対象外にしました（常にすべての機能を利用できます）。**

`feature_allowed()` は当社スタッフに対して常に true を返します。
**ただし「固定」の3機能（面談対象の承認・就業区分の判定／面談結果の記録／報告書への記名）は
これまでどおり産業医のみです。** これは労働安全衛生法にもとづく**医学的判断**であり、
医師でない当社スタッフが行える形にはしていません。ここも当社スタッフに開放する必要がある場合は
ご相談ください。

緑シェルのヘッダーは `margin-left:-72px` でサイドバー（96px）の内側から始まっていたため、
タイトルの左位置が青の20pxに対して44pxになっていました。`-96px` に直して画面の左端から
始めるようにし、青と同じ **左20px・上14px・18px・太さ500・字間2px・色#626262**、

AC設定／設定のカード一覧から「マイアカウント」を外し、代わりに**ヘッダー右上の利用者名
（アバター）をクリック**して開くようにしました。緑・青の両シェルで同じ操作です。

**判定マスタ 編集に「判定追加」ボタンを付けました。**
判定基準カードの見出し行、対象年度プルダウンの右に置いています（`MS.addCriteriaRow()`）。

**登録したアカウント・マスタが消えないようにしました。**
アカウントは元から `hia.db`（データベース）に保存されていますが、**プログラムを新しい版に
差し替えるときに `hia.db` ごと上書きされる**と、登録した内容が初期状態に戻ってしまいます。
そこで配布物には `hia.db` を入れず、初期データを **`hia_initial.db`** として同梱しました。
`hia.db` が無いときだけ、起動時に `hia_initial.db` から作ります（`app.py` の
`restore_initial_db()`）。**既に `hia.db` がある場合は何もしません**ので、
zipを同じフォルダへ展開しても登録済みのアカウント・企業・事業所・加入者は残ります。
あわせて起動時に `backup` フォルダへ **1日1回・最新10世代**の控えを自動で作ります
（`backup_db()`／保持数は環境変数 `HIA_BACKUP_KEEP` で変更可）。起動時のログに
データベースの場所とアカウント件数、控えの保存先を表示します。
なお、この初期データ復元・スキーマ移行・控えは `app.py` の読み込み時に実行するため、
`python app.py` でも waitress 経由でも同じように働きます。

> **お渡ししたzipに `hia.db` を入れてしまっていた版があります。**
> そのzipを既存のフォルダへ展開すると `hia.db` が同梱のものに置き換わり、画面から登録・
> 更新したアカウントが消えてしまいます（原因はzipの作り方で、プログラムの動作ではありません）。
> 以降のzipには `hia.db` を含めません（`hia_initial.db` のみ同梱）。
> 消えてしまった内容は `backup` フォルダーの控えから戻せます。

**控えから戻す**

```
python restore_backup.py           控えの一覧を出して選ぶ（Windowsは restore_backup.bat）
python restore_backup.py --latest  いちばん新しい控えに戻す
```

`backup/hia_YYYYMMDD_HHMMSS.db` の一覧を新しい順に表示し、選んだ控えを `hia.db` に戻します。
戻す前の `hia.db` は `backup/hia_before_restore_YYYYMMDD_HHMMSS.db` として残すので、
やり直しもできます。控えは**起動時に1日1回**作られるため、
**上書きされた日の控え（その日の起動時＝上書き前の状態）**を選んでください。
アプリを止めてから実行し、終わったら起動し直してください。

3枚に分かれていた表を**1つの表**にまとめ（列の幅と見出しがそろいます）、見出し行と機能名の列は
スクロールしても残ります。素のチェックボックスは**トグルスイッチ**に変え、列見出しに

マスタ管理のカードと画面をなくし、区分の定義（01受診情報〜16保健指導の16区分）は

**検査マスタの編集・新規作成画面を1つの表にまとめました。**
